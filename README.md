# Great Roar Safaris

A production-ready Next.js 15 App Router website for a luxury Tanzania tourism company based in the Ngorongoro Conservation Area.

## Stack

- Next.js 15 App Router + TypeScript
- Tailwind CSS 4
- Framer Motion animations
- Shadcn-style UI primitives
- React Hook Form + Zod validation
- Supabase-ready booking/contact storage
- Resend or Nodemailer email notifications
- Next Metadata API, sitemap, robots, OpenGraph, and JSON-LD structured data
- Cloudinary/remote image-ready `next/image` configuration

## Getting Started

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open `http://localhost:3000`.

## Environment Variables

See `.env.example` for all supported variables. At minimum, configure:

- `NEXT_PUBLIC_SITE_URL`
- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `RESEND_API_KEY` or SMTP variables
- `BOOKING_EMAIL_TO`

## Supabase Tables

Create two tables for form storage:

```sql
create table booking_inquiries (
  id bigint generated by default as identity primary key,
  name text not null,
  email text not null,
  phone text not null,
  "safariPackage" text not null,
  "travelDate" text not null,
  travelers int not null,
  budget text not null,
  message text not null,
  created_at timestamptz default now()
);

create table contact_messages (
  id bigint generated by default as identity primary key,
  name text not null,
  email text not null,
  subject text not null,
  message text not null,
  created_at timestamptz default now()
);
```

## Deployment

1. Push to GitHub.
2. Import into Vercel.
3. Add environment variables from `.env.example`.
4. Deploy. The project is configured for static generation where appropriate and serverless route handlers for forms.

## CMS Readiness

Static content currently lives in `lib/data.ts`. Replace this layer with Sanity, Strapi, Firebase, or Supabase queries without changing page-level layouts.

## Local Image Assets

- `public/images/logo`
- `public/images/hero`
- `public/images/safaris`
- `public/images/destinations`
- `public/images/activities`
- `public/images/gallery`
- `public/images/blog`
- `public/images/testimonials`

Use these folders for local image storage and update data/component paths to reference local files as assets are added.
